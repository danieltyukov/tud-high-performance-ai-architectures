\Q{4.1 - Backprop by hand and automatic differentiation}

\Qpart{1} Let $z^1_1 = w^1_{11}x_1 + w^1_{21}x_2 + b^1_1$, $z^1_2 = w^1_{12}x_1 + w^1_{22}x_2 + b^1_2$, and $z^2 = w^2_{11}h_1 + w^2_{21}h_2 + b^2_1$, with $h_i = \mathrm{ReLU}(z^1_i)$ and $y = \sigma(z^2)$. The loss is $\mathcal{L} = \tfrac{1}{2}(y - \hat{y})^2$, so $\partial \mathcal{L} / \partial y = (y - \hat{y})$ and $\partial y / \partial z^2 = y(1-y)$ from the sigmoid derivative.

For $w^2_{11}$ the chain runs $\mathcal{L} \to y \to z^2 \to w^2_{11}$:
\[
\frac{\partial \mathcal{L}}{\partial w^2_{11}}
= \frac{\partial \mathcal{L}}{\partial y}\,\frac{\partial y}{\partial z^2}\,\frac{\partial z^2}{\partial w^2_{11}}
= (y - \hat{y})\,y(1-y)\,h_1.
\]

For $w^1_{21}$ the chain goes one layer further back, through $h_1$:
\[
\frac{\partial \mathcal{L}}{\partial w^1_{21}}
= \frac{\partial \mathcal{L}}{\partial y}\,\frac{\partial y}{\partial z^2}\,\frac{\partial z^2}{\partial h_1}\,\frac{\partial h_1}{\partial z^1_1}\,\frac{\partial z^1_1}{\partial w^1_{21}}
= (y - \hat{y})\,y(1-y)\,w^2_{11}\,\mathbb{1}[z^1_1 > 0]\,x_2.
\]
The ReLU derivative is the indicator $\mathbb{1}[z^1_1 > 0]$, which is why dead ReLU units block any gradient signal from reaching $w^1_{21}$.

\Qpart{2} Automatic differentiation (AD) frameworks compute derivatives by walking a computational graph that records every elementary operation (and its known local Jacobian) performed during the forward pass. Two modes exist: forward mode computes one column of the Jacobian per pass and is efficient when the output dimension exceeds the input dimension, and reverse mode (backpropagation) computes one row per pass and is the right choice for scalar-loss training where the input dimension (parameter count) is huge. JAX, PyTorch and TensorFlow all implement reverse-mode AD by tracing the user's Python function into an intermediate representation, then applying the chain rule along the recorded edges in topological order. The benefit is that the user only writes the forward computation; the framework derives gradients exactly (no finite differencing) and at near-forward cost, which makes complex architectures tractable without any hand derivation.

\Q{4.2 - MLP parameter count and CNN motivation}

\Qpart{1} With $I$ input neurons, $L$ hidden layers of width $H$, and $O$ outputs, the layer-by-layer count is:
\begin{itemize}\setlength\itemsep{0pt}
    \item Input to first hidden: $I H + H$ (weights plus bias).
    \item Between consecutive hidden layers: $H^2 + H$, repeated $L{-}1$ times.
    \item Last hidden to output: $H O + O$.
\end{itemize}
\[
\#\text{params} = IH + H + (L{-}1)(H^2 + H) + HO + O.
\]
For an MNIST-sized example with $I=784$, $L=2$, $H=512$, $O=10$ this gives about $670\text{k}$ parameters, which is already large for a simple toy.

\Qpart{2} Scaling fully-connected layers up is not feasible for harder vision tasks. A single 224$\times$224$\times$3 ImageNet image flattened into a $H=4096$ hidden layer needs $\approx\!617$M parameters in just one weight matrix, so memory and compute explode roughly quadratically with input size. CNNs sidestep this by exploiting two structural priors. First, locality: a feature like an edge is defined by a small neighbourhood of pixels, so each filter only looks at a $k{\times}k$ window. Second, translation invariance: the same edge detector should fire wherever the edge appears, so the filter is applied as a sliding window with shared weights. Together this shrinks the parameter count from $H_{\text{in}} \cdot H_{\text{out}}$ down to $k \cdot k \cdot C_{\text{in}} \cdot C_{\text{out}}$, which is independent of input resolution and several orders of magnitude smaller for typical $k = 3$ or $5$.

\Q{4.3 - Batching, learning rate, fit quality, loss vs accuracy}

\Qpart{1} Two reasons dominate. Averaging the loss over a batch reduces the variance of the gradient estimate, so each step points in a more reliable direction than a single noisy sample would. The second reason is hardware: GPUs and modern CPUs need wide tensors to fill their SIMD or tensor units, so a batch of 128 images runs almost as fast as a single image but does 128 times the useful work. A subtler effect is that very large batches lose the regularising noise of stochastic updates and tend to settle into sharper minima that generalise worse. How the dataset is split into batches also matters. A fixed deterministic order lets the model exploit the order, so the practice is to reshuffle every epoch. If classes are imbalanced, a batch dominated by one class biases the gradient toward that class.

\Qpart{2} If the learning rate $\alpha$ is too large the parameter updates overshoot the loss minimum at every step and the loss oscillates or diverges, often visible as NaN gradients within a few steps. If $\alpha$ is too small the model still moves in the right direction but the loss drops so slowly that it never reaches a useful minimum within a feasible number of epochs. A scheduled learning rate combines the best of both: start large to make quick progress out of the random initialisation, then drop the rate (step decay, exponential decay, cosine schedule, or one-cycle) so the optimiser can settle into a flat region without bouncing around. Warmup at the very start also helps when the gradients are still poorly conditioned.

\Qpart{3} Overfitting means the network has memorised the training set, including its noise, so training accuracy is high while test accuracy stalls or drops. The signature is a widening gap between training and validation curves: training loss keeps falling and validation loss rises again. Underfitting is the opposite, both training and test accuracy stay low because the model is not expressive enough or has not trained long enough; the loss curve plateaus high. Common remedies are regularisation (L2, dropout), early stopping, or more data on the overfit side, and a larger model or more epochs on the underfit side.

\Qpart{4} The loss is a continuous, differentiable proxy for whatever discrete metric (here, top-1 accuracy) we actually care about. It measures the probability the model placed on the correct class, so it is sensitive to the margin of every prediction, while accuracy is binary per example. A model can keep pushing the cross-entropy down by becoming overconfident on examples it already classifies correctly. That extra confidence does nothing for accuracy and in fact tends to coincide with overfitting, where training loss keeps dropping while test accuracy plateaus. That is why the early-stopping signal of choice is validation accuracy or validation loss, not training loss.

\Q{4.5 - Regularised MLP (\texttt{mlp\_adv.py})}

\Qpart{1} \textit{What is dropout?} Dropout randomly zeroes a fraction $p$ of the activations during each training step, then re-scales the surviving units by $1/(1-p)$ so the expected magnitude is preserved. At inference time dropout is switched off and every unit participates. The effect is two-fold: it prevents co-adaptation between neurons (no single unit can be relied on, because it might be dropped any iteration), and it acts as an implicit ensemble over the $2^n$ subnetworks defined by which units are kept.

\Qpart{2} \textit{Is deeper / wider always better?} No. Adding layers and width increases representational capacity but also increases parameters, memory, training time, and the risk of overfitting and of vanishing or exploding gradients (especially without residual connections or careful initialisation). On MNIST in particular, a 512-512 MLP already saturates the dataset, so a 4096-4096-4096 stack would learn nothing useful that the smaller model misses and would just train slower. Depth is most useful when the data has compositional structure that benefits from learned feature hierarchies, which is more true of images, audio and language than of MNIST digits.

\Qpart{3} \textit{AdamW and weight decay.} Adam combines momentum (first moment of the gradient) with per-parameter step normalisation (second moment), so each parameter takes a step whose size is adapted to the scale of its own gradient. AdamW is a small fix on top. Vanilla Adam folds an L2 penalty into the gradient before the moment normalisation, which means the effective weight-decay strength ends up tied to the gradient magnitude and breaks the regularisation it was supposed to provide. AdamW decouples the decay and applies it directly to the parameters at update time, so the weight-decay coefficient now behaves as a clean shrinkage term the way the theory expects. The role of the weight-decay parameter is the same as L2 regularisation: it pulls the weights towards zero, which keeps them small and discourages overfitting.

Even though LeNet-5 has roughly ten times fewer parameters than the wide MLP (61.7k vs 670k), it generalises a few tenths of a percentage point better. The reason is inductive bias. A convolutional layer encodes two priors: pixels close together are more related than pixels far apart, and the same feature can appear at any spatial position. Both priors are true for digit images, so the parameter budget goes into filters that match the structure of the input instead of being burned on irrelevant input-pixel-to-hidden-unit edges. The MLP has none of this. Every connection is learned independently, and most of those 670k parameters re-discover correlations the convolution captures for free. On MNIST that wastage costs only a few tenths of a percentage point. On harder vision data (CIFAR-10, ImageNet) where the structure is richer, the same inductive bias is the difference between a model that trains and one that does not.
